## m5ops
m5指令码用于模拟工作负载和模拟器之间进行通信，最主要的op有：
- exit [delay]: 退出模拟器，[delay] 为退出延迟，单位为cycles，默认为0。
- workbegin: 工作负载开始，通常在模拟器启动时调用。
- workend: 工作负载结束，通常在模拟器结束时调用。
- checkpoint [delay [period]]: 检查点，[delay] 为检查点延迟，单位为cycles，[period] 为检查点周期，单位为cycles，默认为0。


m5ops 主要有两个作用：标注工作负载和在磁盘映像中调用 gem5-bridge

### 在 workload 中使用 m5ops

1. 编译 m5ops library
首先我们要进入 [gem5/util/m5](https://github.com/gem5/gem5/tree/stable/util/m5) 目录,运行 `scons [{TARGET_ISA}.CROSS_COMPILE={TARGET_ISA CROSS COMPILER}] build/{TARGET_ISA}/out/m5` 来编译 m5ops library。
编译出的 `m5`用于命令行，`libm5.a`用于C/C++链接（在C++里使用头文件`<gem5/m5ops.h>`，在GCC编译选项中加上`-Igem5/include` `-Lgem5/util/m5/build/{TARGET_ISA}/out` `-lm5` ）


gem5 的标准库对于部分m5ops有默认行为。例如，当标准库的 Simulator 遇到 m5_work_begin 时，它默认会自动执行 m5.stats.reset()。

这样做的目的是为了清零统计数据，确保性能测量只针对 m5_work_begin 和 m5_work_end 之间的“感兴趣区域”（ROI）。如果想修改这个行为，可以使用 on_exit_event 参数来覆盖它。

## Synthetic Traffic Generation
合成流量组件是一个用于生成合成流量的工具，主要用来模拟内存访问，而绕过cpu的模拟。主要分为LinearGenerator/RandomGenerator(都来自于 AbstractGenerator，在 [gem5/src/python/gem5/components/processors](https://github.com/gem5/gem5/tree/stable/src/python/gem5/components/processors)可以看到所有Generator的实现)，有以下几个参数：
- num_cores: 核心数
- duration: 持续时间
- rate: 内存请求的最大速率
- block_size: 每次访问读写的字节大小
- min_addr/max_addr: 内存地址范围
- rd_perc： 读请求的比例
- data_limit： 数据量限制，如果写0就是无限制

### 创建自己的 Generator

实用函数：`partition_range()`，将一个范围划分为多个子范围，数量为num_partitions

所有的操作都是由 `XXXXCores` 类来完成的，这个类是 Generator 的子类，主要负责生成流量。

我们可以定义自己的 Generator 类，继承自 `AbstractGenerator` 类,在 super().__init__() 中我们需要传递一个列表，这个列表是使用的各个核心。

CPU 核的模拟是 gem5 的核心功能，其部分分类如下图所示：

### SimpleCPU

- Atomic：用于预热和快速前进，忽略访存延迟
- Functional： 有后门访问内存，加载执行二进制文件
- Timing： 模拟时序，模拟时钟和时钟周期

### O3CPU
乱序执行的CPU，模拟了分支预测，缓存，内存访问等。
RiscvO3CPU(from m5.objects import RiscvO3CPU)内部有以下几个参数：
- width：fecth、decode、rename、dispatch、execute、writeback、commit 的宽度
- rob_size：重排序缓冲区的大小
- num_int_regs：整数寄存器数
- num_fp_regs：浮点寄存器数

### Statistics 阅读

- simOps: 模拟操作数，即模拟器执行的指令数
- numCycles: 模拟器执行的时钟周期数
- simSeconds: 模拟器执行的时间，单位为秒(cpu的时间)
- hostSeconds: 主机执行的时间，单位为秒(host的时间)

### **通用的 gem5 CPU 自定义方法 (分层封装)**

在 gem5 中，自定义 CPU 的最佳实践是采用“分层封装”的设计模式。这种方法将 gem5 底层的复杂模拟对象（SimObject）逐步抽象为高层的、易于使用的“组件”（Component）。

这个流程可以分为四个主要层次：

层次 1：定义“CPU 核心” (Core)

  * **目的：** 封装 gem5 底层的 SimObject，将“高级”参数映射到“低级”参数。
  * **做法：**
    1.  创建一个类（例如 `MyO3Core`），它继承自 gem5 底层的 CPU 模型（例如 `RiscvO3CPU` 或 `X86O3CPU`）。
    2.  在 `__init__` 中接收高级参数（如 `width`）。
    3.  将这些高级参数赋值给底层 SimObject 的具体参数（如 `self.fetchWidth = width`, `self.decodeWidth = width` 等）。


```python
# 层次 1：定义核心引擎
from m5.objects import RiscvO3CPU
class MyO3Core(RiscvO3CPU):
    def __init__(self, width, rob_size):
        super().__init__()
        self.fetchWidth = width
        self.decodeWidth = width
        self.commitWidth = width
        self.numROBEntries = rob_size
        # ... 设置分支预测器等
```

层次 2：定义“标准核心” (StdCore)

  * **目的：** 将“核心”注册为 gem5 标准库组件，并指定其指令集（ISA）。
  * **做法：**
    1.  创建一个类（例如 `MyO3StdCore`），它继承自 `BaseCPUCore`。
    2.  在 `__init__` 中，实例化第 1 层的“核心”（`MyO3Core`）。
    3.  调用父类 `super().__init__`，传入实例化的核心和对应的 `ISA`（例如 `ISA.RISCV`）。

```python
# 层次 2：将核心组件化并指定ISA
from gem5.isas import ISA
from gem5.components.processors.base_cpu_core import BaseCPUCore
class MyO3StdCore(BaseCPUCore):
    def __init__(self, width, rob_size):
        # 实例化第1层的核心
        core = MyO3Core(width, rob_size)
        # 注册为标准组件，并指定ISA
        super().__init__(core, ISA.RISCV)
```

层次 3：定义“处理器” (Processor)

  * **目的：** 将“核心”组装成一个完整的“处理器”，并定义它是单核还是多核。
  * **做法：**
    1.  创建一个类（例如 `MyO3Processor`），它继承自 `BaseCPUProcessor`。
    2.  在 `__init__` 中，创建一个包含一个或多个“标准核心”（来自第 2 层）的列表。
    3.  调用父类 `super().__init__`，传入这个 `cores` 列表。

```python
# 层次 3：定义处理器（单核或多核）
from gem5.components.processors.base_cpu_processor import BaseCPUProcessor
class MyO3Processor(BaseCPUProcessor):
    def __init__(self, width, rob_size):
        # 实例化第2层的核心，并放入列表
        cores = [MyO3StdCore(width, rob_size)]
        # 注册为处理器
        super().__init__(cores)
        # (可选) 在这里保存参数，用于后续分析
        self._width = width 
```
层次 4：创建“具体配置” (Configuration)

  * **目的：** 提供最终的、易于调用的“产品”类，固化所有配置参数。
  * **做法：**
    1.  创建一个类（例如 `MyBigCPU` 或 `MySmallCPU`），它继承自第 3 层的“处理器”。
    2.  在 `__init__` 中，调用父类 `super().__init__`，并传入所有**具体的配置数值**。

```python
# 层次 4：定义最终的“产品型号”
class MyBigCPU(MyO3Processor):
    def __init__(self):
        super().__init__(
            width=10,
            rob_size=40,
            # ... 其他具体参数
        )

class MySmallCPU(MyO3Processor):
    def __init__(self):
        super().__init__(
            width=2,
            rob_size=30,
            # ... 其他具体参数
        )
```

## memory system
标准库将 DRAM 等内存模型封装为 `MemorySystem`，有一些已经实现的例子：`muti_channel`、`single_channel`

### 添加新的内存
想要添加新的内存模型，需要保证在[gem5/components/memory/dram_interfaces](https://github.com/gem5/gem5/tree/stable/src/python/gem5/components/memory/dram_interfaces)中有一个对应的实现,然后导入它。
假设我们需要单通道lpddr2，通常写法为：
```python
from typing import Optional

from gem5.components.memory.abstract_memory_system import AbstractMemorySystem
from gem5.components.memory.dram_interfaces.lpddr2 import LPDDR2_S4_1066_1x32
from gem5.components.memory.memory import ChanneledMemory


def SingleChannelLPDDR2(
    size: Optional[str] = None,
) -> AbstractMemorySystem:
    return ChanneledMemory(LPDDR2_S4_1066_1x32, 1, 64, size=size)
```

## Checkpoints

检查点 (Checkpoint) 是 gem5 仿真器在某一时刻的完整状态快照。它将模拟系统（CPU 寄存器、内存、设备状态等）的所有信息保存到磁盘。

其最主要的目的，是**跳过**全系统仿真中极其耗时的**操作系统 (OS) 启动阶段**，从而快速开始对“感兴趣区域”（ROI）的详细性能分析。

### 创建检查点 (Creating Checkpoints)

有两种主要方式来创建检查点：

1.  **使用 m5ops (在模拟系统内部)**

      * 如 `m5ops` 部分所述，可以在工作负载中编译并调用 `m5 checkpoint` 指令。
      * 详情参见 [gem5/util/m5](https://github.com/gem5/gem5/tree/stable/util/m5) 目录。

2.  **使用 Simulator (在 Python 脚本中)**

      * 这是更常用和更灵活的方法，通常与 `on_exit_event` 处理器绑定。
      * 最佳实践是响应 `WORKBEGIN` 事件（即 OS 启动完毕，工作负载即将开始时）来创建检查点。


```python
# 示例：在 OS 启动后 (WORKBEGIN) 创建检查点
from gem5.simulate.simulator import Simulator, ExitEvent

def handle_workbegin():
    print("OS Booted. Taking checkpoint...")
    # 将快照保存到 m5out/my-cpt-dir 目录
    simulator.save_checkpoint("my-cpt-dir")
    # yield True 会继续运行，yield False 会在此处停止
    yield True 

simulator = Simulator(
    board=board,
    on_exit_event = {
        # 将 handle_workbegin 注册到 WORKBEGIN 事件
        ExitEvent.WORKBEGIN: handle_workbegin()
    }
)
simulator.run()
```

### 恢复检查点 (Restoring from Checkpoints)

恢复检查点是在 Python 配置脚本中设置的。你需要指定包含快照的目录路径。

```python
# 示例：从检查点恢复
board.set_kernel_disk_workload(
    kernel=obtain_resource("..."),
    disk_image=obtain_resource("..."),
    # 指定要加载的检查点目录
    checkpoint_path="my-cpt-dir" 
)

# 像往常一样创建和运行模拟器
simulator = Simulator(board=board)
simulator.run()
```

### 检查点兼容性规则 (Compatibility)

**这是使用检查点最关键的部分。** 恢复时的配置必须与创建时的配置在“架构”层面上严格匹配。

  * **必须严格匹配的配置：**

      * **gem5 二进制文件**：必须使用完全相同的 gem5 编译版本。
      * **SimObject 层次结构**：Python 脚本生成的组件树（特别是名称）必须一致。
      * **CPU 核心数**：OS 已经启动并识别了 N 个核心，恢复时必须也是 N 个。
      * **物理内存大小**：OS 已经知道了内存大小，不能更改。
      * **磁盘镜像 / 内核**：必须是创建快照时所用的相同文件。

  * **可以（且推荐）更改的配置：**

      * **CPU 类型 (最常用\!)**：这是检查点的核心价值。
          * 创建时：使用快速的 `CPUTypes.KVM` 或 `CPUTypes.ATOMIC`。
          * 恢复时：切换到详细的 `CPUTypes.TIMING` 或 `CPUTypes.O3`。
      * **CPU 时钟频率**：通常是安全的，被视为微架构细节。
      * **缓存配置 (Classic Cache)**：gem5 的 Classic 缓存状态**不会**被保存在检查点中。因此，你可以在创建时使用 `NoCache`，在恢复时添加完整的 L1/L2 缓存（恢复后缓存是“冷”的）。

### 最佳实践：使用 `SimpleSwitchableProcessor`

为了方便地在 `KVM`（创建）和 `Timing`（恢复）之间切换，标准库提供了 `SimpleSwitchableProcessor`。

```python
from gem5.components.processors.cpu_types import CPUTypes
from gem5.components.processors.simple_switchable_processor import (
    SimpleSwitchableProcessor,
)

# 1. 配置可切换处理器
processor = SimpleSwitchableProcessor(
    starting_core_type=CPUTypes.KVM,    # 启动和创建检查点时使用
    switch_core_type=CPUTypes.TIMING,  # 恢复和详测时使用
    isa=ISA.X86,
    num_cores=2,
)

# 2. 在 WORKBEGIN 处理器中调用 switch()
def handle_workbegin():
    print("OS Booted. Switching to TIMING CPU...")
    m5.stats.reset()  # 重置统计
    processor.switch()  # 执行切换
    yield False       # 必须 yield False 来重载仿真循环

# 3. 正常恢复
# ...
# board.set_kernel_disk_workload(checkpoint_path="...")
# ...
```



## Sampling (采样)

由于详细的 gem5 仿真（尤其是全系统模式）可能非常耗时，采样技术被用来加速仿真过程，同时尽量保持结果的准确性。其核心思想是：只对程序执行中最具代表性或统计上显著的部分进行详细模拟。

主要分为两大类：目标采样和统计采样。

### Targeted Sampling (目标采样)

目标采样的核心思想是：程序的执行行为通常具有阶段性 (Phases)，并且很多阶段会重复出现。我们只需要识别出这些独特的、有代表性的阶段（称为“采样点”），并只对它们进行详细模拟，然后根据它们在总执行中所占的“权重”来加权求和，即可估算出整体性能。

代表性方法：**SimPoint**, **LoopPoint**。

#### SimPoint 工作流 (Workflow) in gem5

SimPoint 使用**固定长度的指令数**（例如 1 亿条）作为“区域”(Region) 来切分程序，然后通过分析“基本块向量”(Basic Block Vector, BBV) 来识别代表点。

**Step 1: 分析 (Analysis) - 收集 BBV 指纹**

  * **目的:** 使用快速 CPU 跑完整个程序，记录每个“区域”的 BBV 指纹。
  * **工具:** gem5 的 `SimPoint` 探针监听器 (`src/cpu/simple/probes/SimPoint.py`)。
  * **方法:**
    1.  配置一个使用 **`ATOMIC` CPU** 的 gem5 脚本 (例如 `simpoint-analysis.py`)。

    2.  将 `SimPoint` 探针附加到 CPU 核心，并指定 `interval` (区域大小，如 1 百万条指令)。

        ```python
        # 在 simpoint-analysis.py 中
        from gem5.components.processors.cpu_types import CPUTypes
        processor = SimpleProcessor(cpu_type=CPUTypes.ATOMIC, ...)
        # ...
        # interval_length = 1_000_000
        processor.get_cores()[0].core.addSimPointProbe(interval_length)
        ```

    3.  运行仿真：

        ```bash
        gem5 -re --outdir=simpoint-analysis-m5out simpoint-analysis.py
        ```
  * **产出:** `simpoint-analysis-m5out/simpoint.bb.gz` 文件，包含了所有区域的 BBV 信息 (格式为 `T:<bb_id>:<inst_count> ...`)。

**Step 2: 聚类 (Clustering) - 寻找代表点与权重**

  * **目的:** 使用外部工具处理 BBV 数据，通过聚类算法找出 K 个“代表性区域”(SimPoints) 及其权重。

  * **工具:** SimPoint 官方工具 (例如 SimPoint 3.2)。

  * **方法:** 运行聚类脚本 (例如 `simpoint3.2-cmd.sh`)，它会调用 SimPoint 工具。

    ```bash
    # simpoint3.2-cmd.sh 内部命令示例
    path/to/simpoint \
        -inputVectorsGzipped -loadFVFile simpoint-analysis-m5out/simpoint.bb.gz \
        -k 5 `# 期望聚类数` \
        -saveSimpoints results.simpts `# 输出代表点文件` \
        -saveSimpointWeights results.weights `# 输出权重文件`
    ```

  * **产出:**

      * `results.simpts`: 列出被选为代表的“区域 ID”及其对应的“SimPoint ID (聚类标签)”。格式: `<Region ID> <SimPoint ID>`。
      * `results.weights`: 列出每个“SimPoint ID”对应的权重 (0 到 1 之间)。格式: `<Weight> <SimPoint ID>`。

**Step 3: 创建检查点 (Creating Checkpoints)**

  * **目的:** 为**每一个**“代表性区域”的**起点**创建一个 gem5 检查点，以便后续快速“瞬移”到该点。
  * **工具:** gem5 的 `SimPoint` 辅助类、`set_se_simpoint_workload` 函数、`simpoints_save_checkpoint_generator`。
  * **方法:**
    1.  配置一个使用 **`ATOMIC` CPU** 的 gem5 脚本 (例如 `simpoint-checkpoint.py`)。

    2.  使用 `SimPoint` 类加载 `results.simpts` 和 `results.weights` 文件，并设置 `simpoint_interval` (必须与 Step 1 一致) 和 `warmup_interval` (用于 Step 4 的预热长度)。

        ```python
        # 在 simpoint-checkpoint.py 中
        from gem5.utils.simpoint import SimPoint
        simpoint_info = SimPoint(
            simpoint_interval=1_000_000,
            simpoint_file_path=Path("results.simpts"),
            weight_file_path=Path("results.weights"),
            warmup_interval=1_000_000 # 为下一步准备
        )
        ```

    3.  使用 `set_se_simpoint_workload` 配置工作负载，它会自动在每个 SimPoint 区间开始时触发 `SIMPOINT_BEGIN` 事件。

    4.  使用 `simpoints_save_checkpoint_generator` 作为 `SIMPOINT_BEGIN` 事件的处理器，它会自动在**属于代表点**的区域起点保存检查点。

        ```python
        # 在 simpoint-checkpoint.py 中
        from gem5.simulate.exit_event_generators import simpoints_save_checkpoint_generator
        dir = Path("simpoint-checkpoints") # 保存检查点的目录
        simulator = Simulator(
            board=board,
            on_exit_event={
                ExitEvent.SIMPOINT_BEGIN: simpoints_save_checkpoint_generator(dir, simpoint_info)
            },
        )
        ```

    5.  运行仿真：

        ```bash
        gem5 -re --outdir=simpoint-checkpoint-m5out simpoint-checkpoint.py
        ```
  * **产出:** 在 `simpoint-checkpoints` 目录下生成多个检查点文件夹 (数量等于 SimPoint 的数量)。

**Step 4: 运行 SimPoints & 预测 (Running SimPoints & Prediction)**

  * **目的:** 使用**详细的 CPU 模型**（如 `O3CPU` 或 `TIMING`）从每个检查点恢复，运行对应的 SimPoint 区间（包含预热和测量），收集性能数据，最后加权求和得到预测值。
  * **工具:** 配置详细系统的 gem5 脚本 (例如 `simpoint-run.py`)，后处理脚本 (例如 `predict_overall_ipc.py`)。
  * **方法:**
    1.  配置一个使用**详细 CPU** (`O3` 或 `TIMING`) 和**匹配基线**的缓存/内存系统的脚本 (`simpoint-run.py`)。

    2.  再次使用 `SimPoint` 类加载 `.simpts` 和 `.weights` 文件。

    3.  使用 `set_se_simpoint_workload` 并**传入 `checkpoint` 参数**来从指定的检查点恢复。

    4.  使用一个“两阶段”的事件处理器 (例如 `max_insts` 生成器) 来处理 `MAX_INSTS` 事件：

          * **第一次触发 (预热结束):** 运行 `warmup_interval` 指令后触发。重置统计 (`m5.stats.reset()`)，安排下一次退出事件（在 `simpoint_interval` 指令后）。
          * **第二次触发 (测量结束):** 运行 `simpoint_interval` 指令后触发。标志测量完成。

    5.  使用 Shell 脚本 (例如 `run-all-simpoint.sh`) **并行**启动多个 `simpoint-run.py` 实例，每个实例通过 `--sid` 参数加载不同的检查点。

        ```bash
        # run-all-simpoint.sh 内部示例
        gem5 -re --outdir=simpoint0-run simpoint-run.py --sid=0 &
        gem5 -re --outdir=simpoint1-run simpoint-run.py --sid=1 &
        # ...
        wait
        ```

#### LoopPoint & ELFies

  * **LoopPoint:** 与 SimPoint 类似，但使用**程序的“循环”**（特别是循环迭代）作为采样单元，而非固定指令数。分析阶段需要额外收集循环执行信息。
  * **ELFies:** 一种特殊的检查点技术，创建\*\*“检查点可执行文件”**，可以非常快速地恢复程序状态到某个点（通常是 LoopPoint 找到的循环入口）。gem5 不支持创建 ELFies，但可以通过 `ELFieInfo` 类**在 SE 模式下运行\*\*预先生成的 ELFies。它通过精确的 PC 地址和执行次数来标记 ROI 的开始 (`start`) 和结束 (`end`)，并自动在开始时重置统计、在结束时转储统计。

### Statistical Sampling (统计采样)

统计采样的核心思想是：不必分析程序的行为模式，而是通过对整个执行过程中**大量、随机或周期性抽取的小样本**进行详细模拟，然后**求平均**来估算程序的**平均性能**（如平均 IPC）。

代表性方法：**SMARTS**, **FSA**。

#### SMARTS 工作流 (Workflow) in gem5

SMARTS 实现了一种\*\*“快进-预热-详测”\*\*的循环。

  * **参数:** 需要预先设定：

      * `n`: 总样本数。
      * `k`: 系统采样间隔 (多少个 `U` 跳过一次)。
      * `U`: 采样单元大小 (每次详测的指令数)。
      * `w`: 详细预热期长度 (每次详测前的预热指令数)。

  * **机制:**

    1.  **快进 (Fast-Forward):** 使用 `ATOMIC` CPU 跳过 `(k-1)*U - w` 条指令 (近似值，取决于具体实现)。
    2.  **切换到详细 CPU:** 例如 `O3CPU`。
    3.  **预热 (Warmup):** 运行 `w` 条指令 (使用 `O3CPU`)，**不统计**。
    4.  **重置统计:** `m5.stats.reset()`。
    5.  **详测 (Detailed Sample):** 运行 `U` 条指令 (使用 `O3CPU`)，**统计**。
    6.  **切换回快速 CPU:** `ATOMIC` CPU。
    7.  重复步骤 1-6，共 `n` 次。

  * **gem5 实现:**

      * 使用 `SimpleSwitchableProcessor` 在 `ATOMIC` 和 `O3`/`TIMING` 之间切换。
      * 使用一个事件生成器 (例如 `smarts_generator`) 配合 `_set_simpoint` 或 `schedule_max_insts` 来精确控制每个阶段的开始和结束，以及 CPU 的切换、统计的重置和转储。参考 `SMARTS.py` 示例。

    **示例 1: 配置 `SimpleSwitchableProcessor` 和计算参数 (类似 `SMARTS.py`)**

    ```python
    import math
    from gem5.components.processors.cpu_types import CPUTypes
    from gem5.components.processors.simple_switchable_processor import SimpleSwitchableProcessor

    processor = SimpleSwitchableProcessor(
        starting_core_type=CPUTypes.ATOMIC, # 用于快进
        switch_core_type=CPUTypes.O3,       # 用于预热和详测
        isa=ISA.X86,
        num_cores=1,
    )

    # 假设已知程序长度和目标样本数
    program_length = 9115640
    target_samples = 50
    ideal_U = 1000 # 设定详测长度
    ideal_W = 2 * ideal_U # 设定预热长度

    # 计算 k
    ideal_region_length = math.ceil(program_length / target_samples)
    ideal_k = math.ceil(ideal_region_length / ideal_U)
    ```

    **示例 2: `smarts_generator` 的核心逻辑 (简化版)**

    ```python
    import m5
    from gem5.simulate.exit_event import ExitEvent

    def smarts_generator(k, U, W, processor):
        warmup_start_offset = U * (k - 1) - W # 近似的快进长度
        warmup_end_offset = W
        detailed_end_offset = U

        while True:
            # --- 阶段 1: 到达预热起点 ---
            print("Switching to Detailed CPU for Warmup")
            processor.switch()
            # 安排预热结束事件 (W 指令后)
            simulator.schedule_max_insts(warmup_end_offset)
            yield False # 重启仿真以应用 CPU 切换和事件

            # --- 阶段 2: 到达预热终点 / 详测起点 ---
            print("Warmup complete. Resetting stats for detailed measurement.")
            m5.stats.reset()
            # 安排详测结束事件 (U 指令后)
            simulator.schedule_max_insts(detailed_end_offset)
            yield False # 重启仿真以应用统计重置和事件

            # --- 阶段 3: 到达详测终点 ---
            print("Detailed measurement complete. Dumping stats.")
            m5.stats.dump()
            processor.switch() # 切换回 Atomic CPU
            # 安排下一次预热起点事件 (需要运行 warmup_start_offset 条指令后)
            simulator.schedule_max_insts(warmup_start_offset)
            yield False # 重启仿真以应用 CPU 切换和事件

    # 在 Simulator 中注册 (假设 simulator 已定义)
    simulator = Simulator(
        board=board,
        on_exit_event={
            # 使用 MAX_INSTS 事件驱动生成器
            ExitEvent.MAX_INSTS: smarts_generator(ideal_k, ideal_U, ideal_W, processor)
        }
    )
    # 首次启动，安排第一次预热事件
    simulator.schedule_max_insts(warmup_start_offset) # 或根据实际需要调整初始快进量
    ```

    *注意：实际的 `SMARTS.py` 使用了 `_set_simpoint` 这种更底层的接口来同时安排多个事件，逻辑会更复杂一些。*

  * **运行与预测:**

    1.  运行 `SMARTS.py` 脚本，它会在 `m5out/stats.txt` 中**多次转储**每个样本的统计数据。

        ```bash
        gem5 -re --outdir=smarts-m5out SMARTS.py
        ```

    2.  运行后处理脚本 (例如 `predict_ipc.py`) 读取所有样本的 IPC，计算**算术平均值**作为预测的平均 IPC，并与基线比较。

        ```bash
        python3 predict_ipc.py --stats_file=smarts-m5out/stats.txt --baseline_file=full-detailed-run-m5out/stats.txt
        ```

        **示例 3: `predict_ipc.py` 的核心逻辑**

        ```python
        import re

        def extract_ipc(stats_file):
            ipcs = []
            try:
                with open(stats_file, 'r') as f:
                    # 使用正则表达式查找所有 IPC 值 (假设格式固定)
                    # 注意：实际 stats.txt 可能包含多次 dump，需要找到所有相关的 IPC
                    ipc_values = re.findall(r"system\.processor\.cores.*ipc\s+(\d+\.\d+).*", f.read())
                    ipcs = [float(v) for v in ipc_values]
            except FileNotFoundError:
                print(f"Error: Stats file not found at {stats_file}")
            return ipcs

        # --- 主逻辑 ---
        smarts_stats_file = "smarts-m5out/stats.txt"
        baseline_stats_file = "full-detailed-run-m5out/stats.txt"

        smarts_ipcs = extract_ipc(smarts_stats_file)
        baseline_ipcs = extract_ipc(baseline_stats_file) # 基线通常只有一个最终IPC

        if not smarts_ipcs or not baseline_ipcs:
            exit()

        predicted_ipc = sum(smarts_ipcs) / len(smarts_ipcs)
        baseline_ipc = baseline_ipcs[0] # 取基线的第一个（通常是唯一一个）IPC

        print(f"Number of samples: {len(smarts_ipcs)}")
        print(f"Predicted Overall IPC: {predicted_ipc}")
        print(f"Actual Overall IPC: {baseline_ipc}")
        error = (abs(baseline_ipc - predicted_ipc) / baseline_ipc) * 100
        print(f"Relative Error: {error}%")
        ```
